# Chrome Web Store — paste-ready submission sheet

Everything below is prepared and checked. Work top to bottom through the
dashboard; each block is meant to be copied verbatim.

**Why this is manual:** Chrome refuses to let any extension script or screenshot
`chrome.google.com/webstore/*` — it fails with "The extensions gallery cannot be
scripted." That is a browser security control, so the submission has to be done
by hand.

Dashboard: <https://chrome.google.com/webstore/devconsole>

**Before you start,** confirm the account has a verified publisher email and the
one-time 5 USD developer fee paid. The dashboard will not accept a submission
otherwise.

### Detailed description
```
Ever read something online and think "did a chatbot write this?" This add-on
shows you which bits gave it away.

HOW IT WORKS

Click the button in your toolbar. The article lights up: every phrase that
matches a known AI writing habit turns yellow. Hover one and it tells you which
habit it spotted. The number on the button shows how many it found. Click the
button again and the page goes back to exactly how it was.

WHAT IT LOOKS FOR

38 patterns in all - the phrases AI writing reaches for again and again:

- "No sign-ups, no downloads, no hassle" - the three-part list
- "It's not just an office, but a small museum"
- "I won't pretend it was smooth" - the humble admission
- "It is important to note that..."
- Words like "delve", "a testament to", "ever-evolving landscape"

A highlight means "worth a second look", not "a robot wrote this". Plenty of
people write this way, and plenty of AI text won't trigger anything at all. It
is a reading aid, not a detector.

YOUR PRIVACY

It cannot spy on you, and that is built in rather than promised:

- It has no access to any page until you click the button - and then only to
  that one tab.
- It has no permission to use the internet, so it cannot send anything anywhere.
- It saves nothing. Close or reload the page and the highlights are gone.
- No accounts, no analytics, no tracking.

GOOD TO KNOW

- It reads the main article. Menus, sidebars and footers are left alone.
- It looks at the page as it is when you click, so on sites that load more as
  you scroll, click once the text has appeared.
- It does not look inside embedded frames.

CREDITS

Free and open source, under the Apache License 2.0.

The pattern-matching engine is Simon Willison's llm-cliche-highlighter. This
extension is a fork of Bruno Renie's llm-cliche-highlighter-extension, which
turned that engine into a browser extension. Both are credited in the licence
file bundled with the extension.

Source code: https://github.com/hwasiti/llm-cliche-highlighter-extension
```

## 2. Privacy tab

### Single purpose
```
To visually highlight phrases on the page the user is currently reading that match known cliches of LLM-generated prose, and to remove those highlights on a second click.
```

### Permission justification — `activeTab`
```
The extension reads and modifies the DOM of the page the user is reading in order to find cliche phrases and wrap them in <mark> highlight elements. activeTab restricts that to the single tab where the user clicked the toolbar button, and only for that visit. No access is held before the click or in the background, and no host permissions are requested.
```

### Permission justification — `scripting`
```
Injects the extension's two bundled files into the active tab when the toolbar button is clicked: core.js, the pattern engine, and content.js, which walks the DOM and wraps matches. The extension declares no content_scripts, so nothing runs until the user clicks. Both files ship inside the package; no remote code is fetched.
```

### Host permissions

None requested — there is no field to fill. If asked, the answer is that the
extension declares no host permissions at all.

### Remote code

**No, I am not using remote code.** Everything executed is bundled in the
package. There is no `eval`, no `new Function`, no dynamic `import()`, no
`fetch`, and no script loaded from a CDN.

### Data usage

Tick **nothing** in the data collection list. Then check all three
certifications:

- [ ] I do not sell or transfer user data to third parties, outside of the approved use cases
- [ ] I do not use or transfer user data for purposes that are unrelated to my item's single purpose
- [ ] I do not use or transfer user data to determine creditworthiness or for lending purposes

All three are true: the extension has no network permission, so it cannot
transfer anything anywhere.

## 5. Known differences from the Firefox listing

Not problems — just so nothing surprises you if you compare the two.

- **Version 1.0.1** on both stores. Firefox 1.0.0 was submitted first and
  automatically disabled when 1.0.1 superseded it; Chrome starts directly at
  1.0.1, so the two stay in step.
- **No `author` key** in the Chrome manifest. Chrome's current manifest
  reference does not document it and the Web Store takes the developer name from
  the publisher account. AMO does use it, so the Firefox build sets it.
- **No Android equivalent.** `gecko_android` is Firefox-only; Chrome for Android
  does not support extensions at all.
- **The short description differs slightly** from the AMO summary because
  Chrome caps at 132 characters and AMO allows 250.

## 6. After it is approved

Bump `version` in the root `manifest.json`, then:

```sh
npm test
npm run package
```

and upload the new `dist/artifacts/llm-cliche-highlighter-chrome-<version>.zip`.
Listing text and images carry over; only the package needs re-uploading.

**Heads-up for local testing:** Chrome 137 removed the `--load-extension`
command-line switch, so `npm run e2e` cannot side-load into a current Chrome.
Load `dist/chrome/` through `chrome://extensions` → *Load unpacked* instead.
